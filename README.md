# AR-DPCBF: Adversarial-Robust Dynamic Parabolic Control Barrier Functions

Simulation and figure-generation code for the paper *"Adversarial-Robust Dynamic
Parabolic Control Barrier Functions for Nonholonomic Robots Against Maneuvering
Obstacles"* (AR-DPCBF).

AR-DPCBF extends the Dynamic Parabolic CBF (DPCBF) of Park, Kim & Panagou by
making the parabolic safe set robust to obstacles that **maneuver** within a
bounded capability set. A kinematic-bicycle robot navigates a field of
maneuvering (unicycle) adversaries; four controllers are compared:

| controller | constraint | penalty | feasibility |
|---|---|---|---|
| **DPCBF** (baseline) | `h >= 0` | – | full |
| **Hard AR** | `h* >= 0` (contracted) | – | reduced |
| **Soft AR** | `h >= 0` | `rho * max(0,-h*)^2` | full |
| **Buffer Soft AR** | `h >= 0` | Huber buffer on `h*` | full |

The adversarial barrier `h*` is the DPCBF barrier `h` with **subtractively
contracted** parameters `(lambda*, mu*)` sized from a worst-case maneuver budget
`kappa` (Theorem 2), so `{h* >= 0}` is an inner approximation of `{h >= 0}`
(safety inheritance, Proposition 3).

## Repository layout

```
ardpcbf/          core library (import these; run everything else against them)
  ardpcbf_core.py   dynamics, DPCBF/AR-DPCBF barriers, Lie derivatives, QP, controllers, adversary
  ardpcbf_run.py    episode runner + (legacy random-adversary) scenario generator
  scenario.py       canonical scenario generator (nearest-adversary definition)
  ardpcbf_estimator.py  online capability estimator (Proposition 10)
experiments/      data-producing runners -> data/*.npz
figures/          plotting scripts -> results/*.pdf,*.png   (Illustrator-editable)
paper/            LaTeX Results section + standalone preview wrapper
results/          reference figures (regenerated by the figures/ scripts)
data/             generated .npz (git-ignored)
docs/             figure index + notes
```

## Quick start

```bash
pip install -r requirements.txt

# self-contained figures (re-simulate on the fly, no data step needed):
python figures/plot_silent_case.py     # deterministic silent-failure contrast (seed 9)
python figures/plot_t0.py              # initial configuration of that scenario
python figures/plot_variation.py       # parabola contraction vs (kappa, ||v_rel||, d)

# data-producing experiments, then their plotters:
python experiments/run_adversary_sweep.py 40      # -> data/adversary_sweep.npz
python figures/plot_adversary_sweep.py            # -> results/fig_adversary_sweep.*

python experiments/run_core_sweeps.py all 40      # capability + density + gamma
python experiments/validity_boundary.py           # -> data/boundary_nagumo.npz  (Theorem 9)
python figures/plot_boundary.py
```

Scripts locate the library and the `data/`, `results/` directories relative to
their own path (via `figures/_bootstrap.py` / `experiments/_bootstrap.py`), so
they run correctly from any working directory. Figures embed editable TrueType
fonts (`pdf.fonttype=42`), so the PDFs open as editable vector art in Illustrator.

## Reproducibility

All randomness is seeded through `numpy.random.default_rng`. The canonical
scenario is deterministic in its integer `seed`:

```python
from scenario import make_scn
scn = make_scn(seed=9, N=10, n_adv=5)   # the n_adv obstacles CLOSEST to the
                                        # robot start are the adversaries
```

The default parameters are the DPCBF Table I values
(`lr=0.20, amax=5.0, beta_max=0.28, vmax=3.5, vdes=2.5, r=1.0`) plus the three
AR-specific settings that must be disclosed: `vmin=1.0` (so the control
authority `c_min = min(amax, vmin^2*beta_max/lr) = 1.40`), `gamma=3.0`, and the
soft-penalty settings `rho=10.0`, `eps_b=0.3`. All are in `class P` of
`ardpcbf/ardpcbf_core.py`.

Metrics are reported on three distinct axes: **barrier violation**
`min_t h < 0` (the silent-failure event, the primary metric), **collision**
`d < r`, and **QP infeasibility**. See `docs/figure_index.md` for the exact
mapping from each paper figure to the script and data that produce it.

## Notes

- `docs/notes_encirclement.md` records a negative result: a symmetric all-sides
  encirclement does **not** separate DPCBF from the soft AR variants (see
  `experiments/encirclement_probe.py`). The deterministic contrast is instead
  shown in a traversal (`figures/plot_silent_case.py`).
- `ardpcbf/ardpcbf_run.py` also contains the original random-adversary
  `make_scenario`; the paper uses the nearest-adversary `scenario.make_scn`.
